# /n8-wiki — Wiki Reconciliation

Do a full pass through the wiki and bring it in line with what the backlog and codebase actually say. Apply updates directly and summarize afterward — the wiki is low-risk to edit and the workflow is autonomous.

Read `${CLAUDE_PLUGIN_ROOT}/reference/state.md` for config conventions, then check `.n8/config.yml`: missing → say `/n8-init` hasn't run and stop; `wiki: opted-out` → say so and stop, wikis are optional. `gh repo view --json hasWikiEnabled --jq .hasWikiEnabled` false → the wiki feature is off in repo settings; say so and stop.

## Voice — read this before writing a word

The wiki is written for humans, by (apparently) a human: informational, plain, first-person-plural where natural. And it is **honest by default — never oversell**:

- A feature that's planned is "planned", not described as if it exists.
- A half-working area says so: "Search works for exact titles; fuzzy matching is planned (#42)."
- Known limitations, missing tests, and rough edges get stated, not omitted.
- No marketing adjectives ("blazing fast", "robust", "seamless"). If performance matters, state the measured number or nothing.

A reader should be able to trust every sentence. When in doubt between flattering and accurate, accurate wins.

## The pass

1. Everything below runs from the project directory in one shell (`gh repo view` resolves the repo from the cwd's remote; the variables set here must survive to step 7). `P=$(pwd); W=$(mktemp -d /tmp/n8-wiki.XXXXXX); git clone "$(gh repo view --json url --jq .url).wiki.git" "$W"`. On a not-found error (match case-insensitively — git prints `Repository not found.`): if `gh repo view --json isPrivate --jq .isPrivate` is true, run `gh auth setup-git` and retry once; a second not-found (or a first on a public repo) means the wiki is **uninitialized** — it exists only after a first page is saved in the web UI, and no API can do it. Then `grep -n 'Pending (n8-wiki): wiki uninitialized' .n8/decisions.md`: a hit with no later `Resolved (n8-wiki): wiki cloned` line → say "still pending since <the date on that line>"; no hit → append, under a `## /n8-wiki — <today>` heading, the plain line `- Pending (n8-wiki): wiki uninitialized — <today>` (no bold, so the grep matches what was written). Either way remind the user of the one manual step and stop; the decisions.md edit lands through the branch-and-PR flow in `reference/state.md`. On a successful clone after a pending line, append `- Resolved (n8-wiki): wiki cloned — <today>` the same way.
2. **Corrections are edited into the page at the point they apply — never appended as a changelog or a "Corrections" section.** If a step is wrong, the step changes; an appended correction leaves the page asserting two things about one mechanism, and the appendix is the half a reader never reaches. History belongs in the commit. A *why* may name what it replaced in one clause ("…in the same transaction, so a rollback never publishes"); a page that is history by design (a decision log, release notes) is exempt. Every corrected claim about a mechanism names the file path and symbol that implements it, in the sentence making the claim, as ``(`src/Publishing/OutboxPublisher.cs`, `OutboxPublisher.Enqueue`)`` — never a line number. After correcting, read the page top-down once; anywhere the body and a correction disagree is a defect.
3. Build the ground truth: `R=$(gh repo view --json nameWithOwner --jq .nameWithOwner)`, `gh issue list --state all --limit 500 --json number,title,state,stateReason,milestone` (if exactly 500 come back, page with `--search` by milestone), `gh pr list --state open --json number,milestone,author --jq '[.[] | select(.author.is_bot | not)]'`, `gh api --paginate "repos/$R/milestones?state=all" --jq '.[] | {number,title,state,html_url}'` for titles, states and links only — per-milestone counts come from the issue list, because the API's `open_issues` includes PRs and bot bumps; issues with no milestone are a last page: `--search 'no:milestone'`. Then the codebase and `.n8/decisions.md`. A sentence is *verifiable* if it names a command, path, symbol, table, service, external system or issue number; every verifiable sentence is checked against the repo or the issue list, and the report counts them. A page came from `/n8-map` if `grep -aoE '<!-- n8-map: [0-9a-f]+ -->|Generated from commit [0-9a-f]+ .* by /n8-map' "$page"` hits (`-a`: ugrep and some greps classify a large page as binary and silently return nothing). `git -C "$P" log <sha>..HEAD --stat` lists what moved since (exit 128 = the SHA is gone from history: every verifiable sentence on that page is checked from scratch). When a page's body changed, or it was checked from scratch, delete the old stamp line *and any sentence that refers to it* ("the commit named below", "line numbers are as of the commit above") and append `<!-- n8-map: $(git -C "$P" rev-parse HEAD) -->` as the last line; a page checked only by diff and unchanged keeps its stamp. A line-number citation in a sentence you touch becomes path plus symbol.
4. Reconcile every page: fix stale claims, dead references, described-but-removed features, wrong setup instructions (verify commands against the repo's actual scripts/config).
5. Add missing pages, linked from `_Sidebar.md` or Home so they are reachable, where a reader would need them — typically: Home (project state overview), Getting Started / local dev setup, Architecture (as-built, including notable decisions and their whys), and per-area pages as the app grows. Don't create pages for the sake of structure; an empty-ish wiki that's accurate beats a full one that isn't.
6. Keep Home's `## Milestones` section current — add it as a table (milestone · state · link, the link being the milestone's `html_url`) if Home lacks one; leave any existing version line alone. From the step-3 issue list: a closed milestone is *done* (with open issues, *done — N open*, flagged); an open one with any issue closed as `COMPLETED` or a non-bot open PR is *in progress*; among open ones with neither, the numerically lowest `M<n>` in the title (not the GitHub milestone number, which is creation order; `M10` sorts after `M3`) is *next*; the rest, including milestones without an `M<n>` prefix, are *planned*.
7. `git -C "$W" status --porcelain` empty → report "wiki already current" and stop (reachable once every map page has been checked at least once and nothing moved). Otherwise one commit naming the pages and the substantive corrections, then push. A rejected push is reported, not retried.

## Report

Summarize what changed: per page, verifiable sentences checked and sentences found wrong; pages updated (with the substantive corrections called out — especially claims that were wrong), pages added, anything found in the codebase that contradicted the backlog (report it; filing is the user's call).
